## What to keep for each workflow

This repo is organized as a stack of workflows, not one monolithic app. The main project flow is described in `README.md:15-48`, and the visual helper is documented in `USAGE.md:665-698`.

| Use case | Must keep | Optional / not required |
|---|---|---|
| 1. Training SwinIR | `main_train_swinir.py`, `main_train_swinir_gan.py`, `models`, `data`, `utils`, `options`, `trainsets`, `superresolution` | `compare_images_side_by_side.py`, analyze_image_stats.py, `kernels` unless using kernel-based degradation models |
| 2. Testing SR outputs | `main_test_swinir_config.py`, `raw_inference.py`, `models`, `utils`, `testsets`, `superresolution` | `compare_images_side_by_side.py`, analyze_image_stats.py |
| 3. Preprocessing imagery | `pleaides_preprocessing`, `preprocessing_pipeline`, `data` support utilities, maybe `trainsets`/`testsets` after generation | `models`, `main_train_swinir.py`, GUI files if not using the UI |
| 4. Running the GUI | `gui`, `backend`, `frontend`, plus the core training/testing folders the GUI calls | analyze_image_stats.py, `compare_images_side_by_side.py` |

## 1) Training SwinIR
Keep:
- `main_train_swinir.py`
- `main_train_swinir_gan.py`
- `swinir`
- `data`
- `models`
- `utils`
- `trainsets`
- `superresolution`

These are the actual training assets. The repo docs clearly present these as the main training entry points in `README.md:20-48`.

Optional:
- `kernels` is only needed if you are using degradation-driven or kernel-based training variants such as SRMD/USRNet-style data loaders.
- `compare_images_side_by_side.py` is just post-hoc visual QA.
- analyze_image_stats.py is just dataset inspection.

## 3) Preprocessing imagery
Keep:
- `pleaides_preprocessing`
- `preprocessing_pipeline`
- whichever dataset folder you are producing into, typically `trainsets` and/or `testsets`

This is the raw-data preparation pipeline, not the SR model itself. The docs mention it as the first major step in `README.md:15-30`.

Optional:
- `models` and training scripts are not needed just to preprocess raw imagery.
- `compare_images_side_by_side.py` is not part of preprocessing.
